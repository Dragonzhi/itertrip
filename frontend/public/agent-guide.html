对话代理

前台客服 · 全站唯一对话入口

你在首页说的每句话都归 ta 接待。贴一篇攻略，ta 一边"打字"给你看、一边把攻略拆成路线数据；信息不够时 ta 会先递上一张澄清卡反问你，绝不瞎猜。

  • 边生成边显示（像微信打字一样流式）
  • 提取攻略 / 修改行程 双模式同一个人接待
  • 输出没按格式来？自动带错误重试 1 次
技术细节

backend/api/chat.py · 双系统提示词 SYSTEM_EXTRACT / SYSTEM_EDIT； 输出走 <<<REPLY>>> + <<<JSON>>> 两段式协议，模型漏标记会全文兜底挖 JSON； 解析失败把错误信息回灌给模型重试一次（自我修复环）；历史只带最近 8 轮防上下文爆炸。

🗺️

规划代理

资深规划师 · 表单直出路线

不想打字？填张表单（去哪 / 几天 / 几个人），ta 直接出一条完整路线，然后自动叫醒定位专员把坐标补全。

  • 每天 3–5 个地点的编排
  • 报价留白——价格中立，由用户手动提供
  • 失败时救场实习生顶上（见下）
技术细节

backend/engine/planner.py · temperature 0.7 / 120 秒； 出口统一跑离谱坐标检测 → 补全 → 高德主动核验三阶段流水线（_enrich_coordinates）； 数据来源（llm / mock）通过响应头带出，不污染行程数据。

📍

坐标代理

定位专员 · 六级降级阶梯

AI 报的坐标常常是"大概在那一片"。这位专员把每个点钉到真实位置，定不下来时层层后退：先查你亲手改过的真值 → 问高德（防同名店搞混）→ 问 AI 的记忆 → 搜网页 → 退到城市中心 → 实在不行诚实标"待确认"。

  • 高德候选打分核名，跨省同名店一律拒收
  • 单条路线最多 40 次请求，超了立即熔断
  • "宁可不给，也不给错"
技术细节

backend/engine/coordinates.py · 接受线 _AMAP_MIN_SCORE=0.72、强匹配 0.85； 地理闸门要求候选落在正确省市（修过「湖南·长沙整条路线被搬去山西」的事故）； 高德致命错误（key 无效/配额尽）1 次即熔断，网络类错误连续 2 次熔断。

探测代理

质检员 · 试你的 key 好不好使

你在设置里填了自己的 AI 服务，ta 负责"试一下"：通不通？模型名对不对？能不能看图（支持截图攻略的关键能力）？试完给你一句明确结论。

  • max_tokens 从 512 逐档往下试，找到可用档位
  • 用 1×1 红色像素图测"视觉能力"
  • 防假阳性：返回网页 HTML 但状态码 200 的情况能识破
技术细节

backend/api/llm.py · 严格校验响应必须含 choices； 视觉探测 2xx = 支持、4xx 且错误体含 vision 字样 = 明确不支持、其他 = 未知按支持处理（宁可信其有）。

记忆服务

档案室 · 跨会话长期记忆（默认关闭）

打开开关后，你每次贴的攻略会被切成一张张"地点卡片"存进本机档案库。下次问"上次那家喝盖碗茶的茶馆"，它翻出相关片段给前台客服参考，答案必须标 [1][2] 出处。你亲手拖对过位置的店会被记成"真值"，以后定位直接命中。

  • 按地点切分存档（不是傻乎乎按字数切段）
  • 注入给 AI 时最多 6 条 / 1200 字，防撑爆
  • 档案按匿名 id 隔离，设置里可一键清空
技术细节

backend/engine/memory_store / memory_embed / memory_ingest.py · 本地 ONNX embedding（bge-small-zh，512 维）+ SQLite 单文件； 检索 = SQL 预过滤（档案+城市+类型）后余弦 top-k； 用户手改坐标经 /api/memory/feedback 变成 geocode 第 0 级真值，不再问 AI。

Mock 规划器

救场实习生 · 没配置也能演

服务器一个 key 都没配时，ta 用一套固定样本撑起完整体验（成都 9 个真实地点轮转），保证"无 key 可演示、断网可联调"。ta 从不冒充真 AI——数据里明晃晃写着「mock 占位」。

  • 确定性输出：同样的输入永远同样的结果
  • 占位数据显式标注，绝不鱼目混珠
技术细节

planner.plan_mock · 规划代理调用失败或无 key 时的降级终点； 对话代理不同：没配置时不静默降级，而是直接报 400 教你怎么配 key（不假装能干活）。

💰

搜索服务

报价跑腿 · 查得到就报，查不到就认

帮你查酒店价格参考。三级数据源：RollingGo → 网页搜索抽取价格 → 都不行就诚实说"没查到，请手动填"。红线：不抓平台价格、不做预订。

  • 每条报价带来源和时间戳
  • 网页摘录永远只是"线索"，不当事实
技术细节

backend/api/search.py · 正则抽取 ¥100–99999 区间； URL 净化防止凭据泄漏进 source_url；M27 起同一服务也供开放时间线索（同样"只给线索不当事实"）。

🗓️

事实检查员

死板会计 · 纯算术，零 AI 零网络

攻略里写"周一闭馆"，而你的出发日恰好是周一？ta 拿小学算术算出星期几，命中就在行程上挂 ⚠️。为什么不问 AI？"不能靠再引入一次幻觉来治幻觉。"日期只有"10月1日"没有年份？按最近未来推断，并明标「推断」、一键可改。

  • 查不出日期就明说"未检查"，绝不假装通过
  • 「法定节假日除外」的模糊说法选择不报（宁缺勿错）
  • 改了日期，旧结论自动消失（幂等）
技术细节

backend/engine/facts.py · 简繁两套闭馆规则解析； 告警写独立 warnings 字段不污染备注；只重写自己写的「闭馆日：」前缀条目。

🚗

交通测距员

测距员 · 问高德拿"快照"

相邻两个地点之间步行 / 公交 / 开车要多久？ta 问高德路径服务，拿回来的是带时间戳的快照——15 分钟内复用，绝不重复花钱花时间。坐标不可信的点直接返回"未知"，不编数字。

  • 预算 24 次请求 / 40 秒，超了礼貌拒绝
  • 并发去重 + 每分钟限速 + 配额熔断
  • 估计值永远标查询时间，不当永久事实
技术细节

backend/engine/transport.py · 只服务 user/memory/amap-high 来源的坐标（trusted()）； TTL 缓存 15 分钟（LRU 512 条）；网络错误对用户可读化，不泄漏 URL 和 key。

③

故事线二：「把博物馆挪到第一天」——谨慎助理的工作方式

这是全系统最新也最讲究的一条流水线（M30）：AI 像一位戴着手铐的助理——只能查资料，不能直接改数据。想动行程必须填《修改申请单》，过两道审查才生效。

💬
你提出修改要求

带完整路线上下文进入助理流程；报价类、坐标纠错类另有专人专办，不走这条线。

🚪
进入「戴手铐」状态

90 秒总预算、最多 3 轮对话、工具调用 6 次 / 60 秒封顶——绝不无限自我对话烧你的 token。

🔍
助理查资料（只读）

四个只读工具：搜地点、查两段交通耗时、搜开放时间线索、看日程冲突。查到的都是"数据"，且不能当事实通过。

📝
交《修改申请单》

想改行程只能提交提案（propose_edits），单子上带本轮编号 + 版本号——防止张冠李戴、防止旧单子重复播放。

🕵️
第一道审查：服务端

参数格式、必去/锁定/已完成站点不许动、预约只能记 pending 不代表订成功、防伪造回执、防重放——整组原子生效或整组拒绝，没有"改一半"。

🖥️
第二道审查：你的浏览器

浏览器是最终裁判：本地再算一遍日程，新冲突 = 拒收原样退回；交通快照必须签名对得上且够新鲜才采信。

✅
落入撤销栈

改动走与手动编辑同一条撤销栈，地图闪烁高亮变化点，随时 Ctrl+Z。

🎭 三种失败剧本（都会被当场戳穿）

只动嘴不动手：模型回复"已经修改成功"却没交申请单 → 系统改写为「模型只返回了文字，没有有效操作」，绝不把嘴炮当成功。

参数乱来：编造不存在的地点、超范围数值 → 校验退回「参数校验失败，整组未应用，请修复」，用剩余轮次自愈。

钱花超了：token 或时间到预算 → 明确回复「行程未修改：已达到本轮查询/重试预算」，绝不悄悄烂尾。

🔐 防伪造回执是什么？

"改成功了"的图章（receipt）只能由浏览器在确认数据真实变化后盖下——模型输出里的任何回执会被系统剥掉。这就是"AI 不能给自己发奖状"。

④

故事线三：「这家店都标到海里了！」——坐标三重兜底

坐标幻觉是旅行 AI 的高发事故（曾把一条长沙行程的 7 个地点搬到山西/河北/北京）。应对方案是三重保险 + 一条铁律。

🗣️
你说出坐标问题

「位置不对」「在非洲」「在海里」……哪怕模型只口头道歉没真改——

🥁
第一重：关键词强制执行

后端识别出坐标类措辞，绕过模型的嘴直接重跑定位链，改完在回复里注明新方位。

🔭
第二重：出路线时就主动扫描

生成完立刻体检：偏离行程中心 >100km、或境内行程里落在境外的点 → 强制重定位。不用等你抱怨。

🕵️
第三重：说了没改二次校验

模型声称"已修正"但你点名的地点坐标一字未动 → 判定"说了没做"，再查一次。

🔐
铁律：你的点谁也不能动

你亲手拖过 / 点过的位置记为「真值」，任何 AI 核验都不覆盖——高德再权威也不行。

📈 真实战果

某真实行程 31 次高德请求、写入 21 处、距目的地 >300km 的错误坐标从 7 处降到 0；而合法的远点（长沙行程里的张家界）因"改回去更近目的地"判据不成立，安然无恙。

小白词典：13 个 Agent 工程知识点，本仓怎么落地的

这些词面试常问。每条先说人话，再说 IterTrip 里长什么样（⤷ 后面是代码位置）。

工具调用Tool Calling

不让 AI"说"要做什么，而是给它一套有严格参数格式的工具，让它按规矩点名调用。

⤷ 4 个只读工具（搜地点/查交通/搜线索/看日程）+ 提案制，agent_tools.py

结构化输出Structured Output

AI 的回答必须能被程序解析。双保险：模型支持"原生工具调用"就用标准的，不支持就自动切回两段式文本协议。

⤷ <<<REPLY>>>/<<<JSON>>> + 能力探测回退，agent_turn.py

有界循环Bounded Loop

Agent 干活必须有"下班时间"：最多 3 轮对话就收工，防止无限自我对话烧钱。

⤷ agent_turn.run() 三轮上限 + 16k token 软停 + 90 秒总预算

校验优先于执行Validate before Apply

模型只出"建议"，真正写入由确定性代码完成；服务端和浏览器各审一遍，全过才落账。

⤷ agent_ops.validate（服务端）+ shared/agent.js prepare（浏览器）

防伪造回执Anti-forgery Receipts

"改成功"的图章只能由浏览器在确认真实变化后盖下；模型从文本里伪造的图章会被系统剥掉。

⤷ agent_receipts + strip_generated()，模型不能给自己发奖状

提示注入防御Prompt Injection Defense

用户贴的文本里可能藏着"忽略以上规则"。共识：把它当数据而不是命令。

⤷ 现状：新改行程流程有此防线；老的提取路径还没加 ⚠️（M35 计划中）

RAG 记忆检索增强生成

回答前先翻档案库找相关片段，答案必须标 [1][2] 出处；注入量有硬上限防撑爆。

⤷ 实体级切分 + 本地 embedding + ≤6 条/1200 字，memory_*.py

降级链Fallback Chain

每个外部依赖都有层层退路：高德挂了用 AI 知识，AI 不行搜网页，再不行退城市表——最差也要诚实承认失败。

⤷ 坐标六级链 + 供应商四级链（你的 key→服务器→免费源→mock）

决策可观测Observability

每轮 AI 工作写"工作日志"：模型来源、坐标出处、重试、耗时，前端可展开、刷新不丢。静默兜底必须变成可见决策。

⤷ SSE trace 协议，≤60 步，chat.py _trace_step

确定性服务分工Determinism

算术题不问 AI：闭馆日是纯算术，交通耗时问高德拿快照，网页摘录永远只是线索。

⤷ "不用再引入一次幻觉来治幻觉"，facts.py / transport.py

澄清式交互Clarification

信息不足不瞎猜，输出结构化问题卡（文本/单选/多选/日期）让用户补答，答完再继续。

⤷ need_more_info + questions[]，前端渲染澄清卡

「说了没做」兜底Anti-claim Guard

AI 嘴上说"已完成"但数据没变？三类场景各有硬兜底：改路线只回叙述→语义重试；报价没写→确定性写入；坐标没改→强制重查。

⤷ M22 三件套，chat.py / hotel_price.py

评估Evals

不靠"感觉变好了"：35 个行程约束场景 + 9 个模型交互场景自动回归。诚实声明：合成测试 ≠ 真模型成功率。

⤷ backend/_check_m30.py + m30-core.mjs；真模型质量评估在计划中
