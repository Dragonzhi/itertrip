# M21 · 地点的自主修正（明显偏离用户指定的目的地）

> 版本：v1.0 · 2026-09-14 · 适用代码库：`backend/`（FastAPI）+ `frontend/`（React 18 + Vite）
> 触发来源：用户反馈「**agent 应该要自主地可以判断地点的位置明显远离了用户要求的地点的时候，做出主动的修正**」
> 结论：判据从「行程内部自洽」升级为「**与用户要求的目的地一致**」，并在**每次生成/改路线**时自动执行，
> 不再依赖用户点「🔍 校准坐标」。

---

## 1. 需求解读

M20 修好了「新写入的坐标不许出省」，但**已经写坏的**坐标仍然只能靠用户手动点「校准坐标」修。
用户这次要的是：**不用点任何按钮，代理自己判断「这个点明显不在我要去的地方」并改正。**

三个要害：
1. 判据必须是**用户要求的目的地**（route.trip.destination），不是行程内部自洽性；
2. 动作必须**自主**（正常管线里就跑，而不是一个可选按钮）；
3. 必须**可见**（决策轨迹里写清「为什么动了我的坐标」），并且**可撤销**（走同一条撤销栈/撤销操作）。

---

## 2. M20 留下的三个缺口（实测确认）

**R1 · 判据用的是行程中位数，整条路线都错时一起失效。**
阶段①的离谱检测是「偏离行程有效坐标中位数 > 100km」。把用户那份行程里 7 个跨省点**单独**当作一条行程
（中位数因此落在华北）后实测：阶段①只认出并修好了 3 个，另外 4 个（北京/天津/保定/廊坊一带，离中位数 <100km）
完全没被怀疑过 —— 而它们同样在别的省。

**R2 · `amap/high` 标签被当成「已核验」，导致坏坐标永远躲过复核。**
阶段③有一条优化：`source == "amap" and confidence == "high"` 就跳过（本意是「本次刚由高德写入，别问第二遍」）。
但 M20 事故里那些被写坏的坐标**恰好也标着 `amap/high`** —— 于是用户那份文件导入后再怎么改路线，
它们都不会被重新看第二眼。这正是「不点按钮就永远修不好」的直接原因。

**R3 · 「校准坐标」是强制复核（`force_verify`），但它是用户发起的，不是代理自主的。**

---

## 3. 修复

### 3.1 目的地参照点 `destination_anchor()`

先按城市查内置城市表（46 城），**城市不在表里时退到省会**（新增 `_PROVINCE_CENTER`，34 个省级行政区 →
省会中心），都解析不出则返回 `None`（不做地理否决，行为同旧版）。

- `湖南·长沙` → 长沙市中心
- `河南·洛阳` → 郑州（省会是这一带的地理参照，不是「洛阳的中心」）
- `日本·东京` / `东南亚` → `None`

> 省界无法用「距省会距离」精确表达，所以省会锚点只用于**判断依据**，且必须配合 3.2 的「必须更靠近」才允许改动。
> 它**不参与** `_region_ok` 的候选放行（那会把省界外的邻省 POI 也放进来）。

### 3.2 第三条独立佐证：**明显离位**（记 `redirect`）

阶段③原有两条「允许搬」的佐证（名称完全一致 ≥0.99、候选池 ≥3 条互相同意）。M21 增加第三条：

```
wrong_place = 现有坐标与高德给出该地点的位置相差 > _VERIFY_WRONG_KM（200km）
closer      = 改回去之后更靠近「用户要求的目的地锚点」（没有锚点时退到行程中位数中心）
→ 两者同时成立 ⇒ 采用高德坐标，记 action="redirect"
```

依据：同城偏差不可能是 200km 量级 —— 这不是「偏了」而是「被放错了地方」。
反过来，**只有 "wrong_place" 而没有 "closer" 时宁可不动**，这样合法的远点（例如长沙行程里的张家界天门山）
不会被同名的异地 POI 搬走。

### 3.3 跳过条件收紧：标签 + 位置自洽，两个条件都要满足

```python
# 旧：来源标签是 amap/high 就跳过（M20 事故里被写坏的坐标恰好也满足这个标签）
# 新：标签是 amap/high **且** 该点离用户要求的目的地 ≤200km，才跳过
dest_far = anchor is not None and 距锚点 > _VERIFY_WRONG_KM
if not force_verify and obj.source == "amap" and obj.confidence == "high" and not dest_far:
    continue
```

成本控制：正常行程里所有 `amap` 点都离目的地很近 → **0 次额外请求**；
只有「离目的地 200km 以上却标着 amap」的点才会追加一次核验（正是需要重新审视的那些）。

### 3.4 可见性

- 轨迹步文案：`redirect` → 「**明显偏离用户指定的目的地，已改回**」（`chat._GEO_ACTION_TEXT`）；
- 阶段汇总：`· 改回目的地 N 处`（`chat._geo_summary_text`）；
- 地图/时间线的来源徽标不变（`amap/high` 仍是「高德核验」），改动仍走前端同一条撤销栈。

## 4. 实测

### 4.1 A 场景：整条路线都在错误省份（中位数失效）

把用户行程里 7 个跨省点**单独**当一条行程（目的地 `湖南·长沙`），调用**默认**（`force_verify=False`）管线：

| 地点 | 结果 | 动作 |
|------|------|------|
| 五一广场 | 28.1965, 112.9773（距长沙 1km） | `replace`（阶段①） |
| 天心阁 | 28.1848, 112.9819（1km） | **`redirect`** |
| 费大厨辣椒炒肉（悦方/国金街店） | 28.1927, 112.9789（0km） | **`redirect`** |
| 文和友（海信广场店） | 28.1891, 112.9697（1km） | **`redirect`** |
| 湖南米粉街（韭菜园） | 28.1964, 112.9882（1km） | **`redirect`** |
| 毛泽东铜像广场 | 27.9038, 112.4872（58km，韶山） | `confirm` |
| 毛家饭店（韶山冲） | 28.2057, 112.9720（2km） | `replace` |

**写入 7 处，仍距长沙 >300km：0 个**（M21 之前这个场景只能修好 3 个）。

### 4.2 B 场景：用户那份真实行程，走默认生成路径（不点任何按钮）

`高德请求 31 次 · 写入 21 处`，**距长沙 >300km 的点：7 → 0**。
其中 `韶山南站 / 毛泽东故居 / 滴水洞`（55~59km，标签已是 amap/high 且位置自洽）**直接跳过、零请求**，
验证了 3.3 的成本控制。

## 5. 参数与契约

| 参数 | 值 | 位置 | 说明 |
|------|-----|------|------|
| `_VERIFY_WRONG_KM` | 200 | `planner.py` | 现有坐标与「高德说该地点所在的位置」相差超过此值 → 判定放错了地方 |
| `_PROVINCE_CENTER` | 34 项 | `coordinates.py` | 省级行政区 → 省会（仅作参照点，不参与候选放行） |
| `redirect` | 新动作 | `planner._geo_rec` / `chat._GEO_ACTION_TEXT` | 「明显偏离用户指定的目的地，已改回」 |

契约变化：`_enrich_coordinates` 的坐标记录新增 `action="redirect"`（前端按未知动作回退显示，无破坏性）；
`destination_anchor()` 增加省会回退；**无新增环境变量**。

---

## 6. 边界与偏差

1. **目的地解析不出省市**（如「东南亚」「日本·东京」）→ 没有参照点 → 不做地理否决，退回 M20 的中位数判据
   （宁可不动，也不拿一个假参照点乱改）。
2. **境外行程**同理：M21 的自主改回只在能解析出中国省市时生效；境外同名 POI 的误配仍由 M20 的
   地理闸门「无城市约束时至少落在中国境内」兜底。
3. **省会锚点有固有误差**（省会比城市中心粗，且大省跨度大），因此只用于「必须更靠近」的判据；
   实测反例（河南·洛阳行程里的少林寺 vs 信阳同名 POI）已被 `check_geocode[16]` 覆盖为「不动」。
4. **酒店同样纳入**：阶段③ 的核验对象本来就包含酒店（`geo:dN-hotel`），因此 M21 的「明显离位」
   判据对酒店一视同仁；而阶段① 的「偏离中位数」检测仍只针对地点（酒店沿用旧行为，不在本次范围内）。
5. **未改**：M20 的行程地理包络、置信度跟随匹配分、`force_verify`（「校准坐标」按钮语义不变，
   仍然是「连本次刚写入的点也复核」）。
