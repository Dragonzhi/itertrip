# M22 · 出发日期与闭馆日冲突检查

> 版本 v1.0 · 2026-09-14 · 定位：IterTrip 事实层的第一个可判定切片
> 一句话：把「周一闭馆」这类写在行程文本里的营业规则，与「这一天究竟是星期几」对上；
> **判据全是确定性算术，不调用任何模型或网络** —— 治幻觉的第一原则是别再加一次幻觉。

---

## 1. 问题：一条真实行程在自我打脸，而系统不知道

M21 收尾时对真实交付物做了一次事实层审计（`test-artifacts/国庆长沙6日游_坐标校准.json`，29 个地点），
发现坐标之外的问题：

| 事实 | 现状 |
|---|---|
| `TripInfo.dates` | **自由文本**「10月1日下午 – 10月6日晚上（国庆假期）」—— **不含年份**，算不出星期 |
| 后端 weekday 逻辑 | **零**（全仓 `weekday|isoweekday` 零命中） |
| `place.ticket` | 自由字符串，零核验零溯源；闭馆日、小交通价、人均消费全塞在里面 |
| `place.time` | 契约要求写「营业时间」，真实数据 29/29 全是**参观时段**（「16:30–17:30」） |

**直接后果**：`10月1日` 起算 → D5 = 10月5日 = **周一**（2026 年；已核算 2026-10-01 为周四）。
而 D5 的第一个点是「谢子龙影像艺术馆」，它**自己的 `ticket` 字段就写着「免费，需公众号预约（周一闭馆）」**。
同一天的「李自健美术馆」现实中同样周一闭馆。**行程与它自己记录的事实矛盾，没有任何机制发现。**

> 这不是模型能力问题。把它交给「多模型交叉核查」也没用：三个模型读到的都是同一句
> 「周一闭馆」，谁都不会去算 2026-10-05 是星期几。**缺的是算术，不是智能。**

## 2. 设计取舍：推断而非追问

日期缺失有两条路：**追问用户**（复用 M17 澄清卡）或**就近推断**。本项目选了后者 + 可见可改：

- **推断口径**：完整日期（含年份）= 用户给定（`date_source=user`）；只有月日或阳历节日名 =
  「就近未来」取年份（已过则明年，`date_source=inferred`）—— 即「默认就是今年」；
- **绝不静默**：界面显式标注「推断」，点一下日历就能改；改完立即重算并走**同一条撤销栈**；
- **定不了就是定不了**：解析不出日期时 `checked=False`，界面显示「未检查闭馆日」，
  **不能假装通过**（M19「静默兜底必须变成可见决策」的同一原则）；
- **不猜农历**：元旦/清明/五一/国庆是阳历固定；春节/端午/中秋一律不猜 —— 宁可让用户填。

选它的理由：追问会给每一次「贴攻略」都加一步，而绝大多数行程并不关心闭馆日；
「默认今年 + 标明是推断 + 一键可改」在零打扰与不撒谎之间同时成立。

## 3. 实现

### 3.1 新模块 `backend/engine/facts.py`（纯确定性）

- `parse_closures(text)` —— 解析 `(周|週|星期|礼拜|禮拜) + 星期几 + (闭馆|闭园|不开放|休馆|休息|闭关)`，
  简繁两套字形；同时判定附近的例外声明（`法定|节假日|黄金周… + 除外|正常开放|不休`）；
- `resolve_start_date(*texts, today)` —— 完整日期 → `user`；月日/阳历节日 → 就近未来，`inferred`；
  都取不到 → `("", "")`；
- `annotate_route(route, hint, today)` —— 定日期（写回 `trip.start_date` / `trip.date_source`）→
  逐天算日期（D1 = 出发日）→ 扫 `ticket + note + time` → 星期命中就写 `place.warnings`。

**幂等**：每次只清理自己写的 `闭馆日：` 前缀条目，重复调用不重复写；改日期后旧结论自动消失
（这正是「改一下日期告警就没了」的机制）。

### 3.2 契约（可选字段，向后兼容 —— 沿用 M19 `source/confidence` 的先例）

```
TripInfo.start_date: str = ""      # YYYY-MM-DD，给机器算星期用
TripInfo.date_source: str = ""     # user | inferred | ""
Place.warnings: list[str] = []     # M22 事实告警
```

**刻意不复用 `note`**：审计的结论之一就是 `note` 已被 `【坐标待确认】` 污染，
继续往里塞系统告警是坏味道。事实告警走独立字段 + 独立渲染（红/琥珀色，与坐标徽标视觉区分）。

### 3.3 端点与挂载点

- `POST /api/route/datecheck`（`{route, start_date?}`）：传 `start_date` 视为用户给定并同步
  `trip.dates` 文本；不传则推断。**不调 LLM、不调高德**（响应里 `amap_calls: 0` 供测试断言）。
- 生成路径自动挂载：`planner.plan()`（表单）、`chat.py` 提取模式出口、`chat.py` 改路线出口
  —— 每处独立 `try/except` 兜底，失败在决策轨迹里留 `facts-error` warn 步，不静默、不阻断出路线。
- 前端：规划页头部新增**日期卡**（`CalendarPicker` + 「推断」/「已确认」/「⚠️ N 处闭馆日冲突」/
  「未检查闭馆日」四种状态）；时间线与地图气泡渲染 `warnings`；导入的旧 JSON / 导出的 HTML
  进页面自动补跑一次（每条行程只跑一次）。
- 导出模板 `route_map.html`：顶部 meta 显示 `📅 2026-10-01（推断）`，地点条目渲染告警；
  导出页内的编辑弹窗**不重算**告警（模板是独立 JS，本轮范围外，已在文档写明）。
- 决策轨迹新增 `kind="facts"`（图标 🗓）与 `stats.fact_warnings`：检查不了就写「未提供出发日期，未检查」。

## 4. 实测

| 场景 | 结果 |
|---|---|
| 离线用例 `test-artifacts/check_facts.py` | **10/10 全绿**（解析/不误报/推断/精确匹配/幂等/例外抑制/无日期/跨年/真实交付物/汇总文案） |
| 真实交付物（不传日期） | 推断 `2026-10-01`（`inferred`）→ **恰好 1 处冲突**：D5 谢子龙影像艺术馆 · 2026-10-05 · 周一 |
| 真实交付物（改成 `2025-10-01`） | **冲突归零**（2025-10-05 是周日）—— 证明是算出来的，不是写死的 |
| 端点 | `amap_calls=0`；非法日期 400「出发日期格式应为 YYYY-MM-DD」 |
| 真机探针 `probe_datecheck_ui.cjs` | **19/19**：自动推断 → 手选 10/5 出现告警（头部徽标 + 时间线 chip）→ 改 10/6 告警消失 → **撤销可回到告警那一帧** |
| 导出探针 `probe_export_warn.cjs` | **9/9**：导出 HTML 顶部显示 `📅 2026-10-01（推断）`、地点条目渲染告警、页面零脚本错误 |
| 回归 | `check_geocode` 17/17 · `check_trace` 9/9 · `api_smoke` 22/22 · `check_schema`/`_e2e` · `check_export_filename` · `check_m15` · `check_memory_api` · `routeImport.test` · `check_import.test` · `probe_recheck_ui` 全绿 |

`trip.dates` 文本与人手选日期会同步（`2026-10-05 – 2026-10-05` → 单日只写一天），
避免「给人看的文本」与「用于计算的日期」两处对不上。

## 6. 边界与不覆盖（诚实清单）

- **农历节日不推断**（春节/端午/中秋）—— 没有农历表，不猜；
- **一次性闭馆公告**（「10月1日闭园」）不识别 —— 需要真正的日期区间解析，另行排期；
- **「周一闭馆（法定节假日除外）」抑制硬告警**，只计入 `skipped` 并在汇总说明条数 ——
  我们不知道法定假日的准确表，宁可不报也不误报（国庆期间很多博物馆恰恰周一开馆）；
- **顿号枚举**（「周一、周二闭馆」）只认到「周二闭馆」一条；
- **导出 HTML 的编辑弹窗不重算**告警（只在应用内重算）；
- 本轮**不覆盖**：营业时间 vs 参观时段冲突、单日时段重叠/动线检查、事实字段的记忆库护栏
  （`note`/`ticket` 仍会被 M18 记忆库切成 `place_card` 并以 `[n]` 引用注入，见审计 P3）。
