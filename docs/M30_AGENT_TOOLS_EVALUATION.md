# M30 · 受约束操作、只读工具与场景评估

> 2026-10-01 · 已实现；自动化验证与本地构建通过。真实模型／网关的能力与途中使用效果仍待人工验收。

## 用户会看到什么

- 在规划页说「把春熙路休息点停留改成 45 分钟」，明确单项编辑直接进入原来的撤销栈，回复从实际 diff 生成，显示具体分钟数。
- 组合修改／新增草稿／记录预约先展示预览；应用整组只产生一帧撤销，取消不动路线。
- 固定预约、已完成访问、不存在的地点或旧路线版本会拒绝。自动重排缺少新相邻段的真实耗时、日期或开放资料时也拒绝，不假装可行。避雨移动另复用 M29 检查，要求已有当前预报／确认属性且风险减少；已知天气也不能被普通重排改成更大暴露。
- 查询天气／交通／地点／开放线索是只读操作。轨迹记录实际调用、来源、时间、HTTP 次数与失败；结果未知就显示未知。
- 预约只记录为「待确认」，不会替用户订票。新增点坐标为草稿，需按名称定位后确认。
- 停止生成、生成期间路线变化、预览期间进度变化、只有成功叙述、合法但无效的操作都不会显示应用成功。离开规划页也会停止该轮编辑。

坐标修正、酒店报价、备注等原有完整路线编辑仍保留原链路。其成功提示现在同样取决于客户端真实应用的 diff；后端把产出称为候选。

| `backend/engine/agent_tools.py` | 只读适配器、统一结果、查询预算、去重和实际交通证据；复用已有服务 |

没有引入 Agent 框架、Node 服务端运行时、额外模型或外部 MCP。时间求解仍由 M27 的同一份 `IterTripSchedule` 执行；服务端 `check_schedule` 返回浏览器发送的同版本派生日程，并注明这是确定性输入计算，不是外部核验。**它不能代替应用前的重新计算**。

### 协议

`POST /api/chat` 新增可选字段 `agent_version`、`completed_ids`、`agent_schedule`。规划页会发送；旧调用方不受影响。命中领域编辑／相关查询意图时进入 M30，其余保留旧链路。当前识别为有边界的中文意图匹配，不宣称理解所有口语变体。

模型上下文保留身份、访问安排与事实约束，省略原始小时网格、交通快照、酒店报价和事务记录；需要精确时间时查同源日程工具，需要外部数据时查只读服务。完整路线仍用于业务校验，不因省略上下文而删数据。最近 8 条历史作为数据传入，每条最多 3000 字符。

普通双段输出：

```json
{
  "proposal": {
    "transaction_id": "本轮提供的编号",
    "base_version": "本轮提供的版本",
    "actions": [
      {"op": "set_duration", "place_id": "访问ID", "minutes": 45}
    ]
  }
}
```

也可输出唯一 `tool: {name, arguments}`，服务端执行后回传结果。一次输出不得混合查询与编辑。

工具目录：

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `search_place` | `name` | 目的地由路线决定，只查高德 POI；无额外 LLM 降级、无自动坐标写入 |
| `query_transport` | `from_id`、`to_id`、`mode` | 坐标由访问 ID 查得；复用 M26 服务及缓存／熔断 |
| `query_weather` | `place_id` | 复用 M29；未配置、无可信位置或失败时未知 |
| `search_facts` | `place_id` | 官方开放／预约资料线索；不升级为用户确认事实 |
| `check_schedule` | `day` | 同版本派生日程；没有客户端结果时未评估 |
| `propose_edits` | 领域候选 | 原生调用中的提案出口；不是提交／预订接口 |

统一查询结果带 `status`（ok／unknown／error）、`data`、`reason`、`base_version`、`queried_at`、`source`、`http_calls`、`cached`、`elapsed_ms`。成功的网页查询仍是未核实线索。模型不能自行构造交通证据：只有适配器实际取得的结果才通过终帧 `agent_evidence` 提供；候选采用前检查版本、端点完整签名、可信坐标和 15 分钟时效。只读调用不会改当前路线，采用依据与应用候选在同一帧提交。

操作目录：`move_place`、`set_duration`、`lock_visit`、`set_reservation`、`add_place`。不开放任意 JSON 路径、执行脚本或任意 URL 抓取。数字参数拒绝布尔值；未知参数、无效日期／时段、缺失或重复身份均拒绝。日期和预约值来自用户输入或待确认预览，不允许模型制造 confirmed。服务端先拷贝并整组校验，浏览器再对实际最新状态重新验证。

### 供应商能力和预算

默认 `.env` 中 `ITERTRIP_AGENT_PROTOCOL=protocol`，兼容现有双段 JSON。明确支持 Chat Completions 函数调用的供应商可设置 `tools`：传 `tools` 和 `parallel_tool_calls=false`。只接受单个工具调用；出现 400／422 且错误指明不支持工具相关参数才回退，鉴权／配额错误不会冒充能力不足。拒绝请求也消耗一轮预算，回退可见于轨迹。

原生调用使用兼容的 JSON Schema，不强制供应商 `strict=true`；所有输出仍经过同一份严格 Pydantic 和业务检查。遵循 [OpenAI 函数调用文档](https://developers.openai.com/api/docs/guides/function-calling) 的“模型提出调用，应用执行并回传结果”流程。未用 Responses／托管 Agent，接口保持 OpenAI 兼容 `/chat/completions`。

| 预算 | 当前值 |
| --- | --- |
| 单轮总耗时 | 90 秒；心跳仍每约 2 秒发送 |
| 模型请求次数 | 最多 3 次，含能力拒绝和修复；一个模型，无模型切换 |
| 单次模型请求 | HTTP 35 秒、`max_tokens=1800`、初始上下文 ≤100,000 字符 |
| 只读工具 | 最多 6 次、从本轮开始起 60 秒内完成、单次 ≤15 秒；顺序调用，重复查询缓存 |
| 上下文结果 | 每份工具结果 ≤24,000 字符；超限返回未知，不能截断后称事实完整 |
| 操作 | 一组 1–12 个；模型操作 JSON ≤16,000 字符 |
| token 停止阈值 | 已报告累计 >16,000 时停止后续查询／提案；不是供应商账单的精确硬上限 |

用量字段只有供应商真实返回才累计。`usage_complete=false` 表示存在未报告用量；界面写「已报告 token」，金额没有单价配置时为 null／未知，绝不填 0 元。工具超时后实际请求次数无法确定时也为 null。天气服务原有共享 in-flight 查询可能在调用者取消后完成缓存，不会再提交该轮路线。

网页摘录、历史攻略和工具结果按数据处理，不能覆盖系统指令。候选只允许上述有限操作；外部数据无法写入确认事实、订票状态或凭据。

### 版本、重放和撤销

版本是浏览器为本轮路线快照分配的**不透明编号**，不是数据库 revision、鉴权或密码学哈希。无状态后端只能检查候选是否引用本轮编号；最后一关是浏览器 `isCurrent(expected)`／历史栈引用检查。预览另外检查已完成访问集合，应用时重算事实和交通时效。

路线新增可选 `agent_receipts: [{id, payload}]`。payload 为规范化操作 JSON，用于辨别同编号不同意图；没有 API Key／原始攻略／网页全文。同一事务重放无改动，新地点 ID 从事务编号和动作序号派生，不重复新增。记录最多 1000 条，浏览器另限 500,000 字符，达到预算拒绝新增记录而不静默淘汰。撤销恢复记录和数据，重做恢复同一事务；撤销后的重新应用视为新的真实编辑。

记录随当前路线持久化和 HTML 导出，旧路线可没有字段；原完整路线编辑不得抹掉或伪造它。待应用预览留在内存，刷新后不恢复应用按钮，以免对新状态自动提交。用户手动清掉记录或删除它再导入属于新路线，无法保证跨这类人工重置继续去重。

## 自动化验收与评估

执行：

```powershell
.venv/Scripts/python.exe -m backend._check_m29
.venv/Scripts/python.exe -m backend._check_m30
cd frontend
node scripts/m30-core.mjs
node scripts/m30-dom.mjs
npm run build
```

- 后端：严格参数、固定／完成保护、编号重放、只读适配器、缓存、真实超时取消、实际 SSE 原生／协议回退／查询回传、请求与 token 阈值、模型仅说成功、无效 JSON、合法 no-op、中断与大快照上下文瘦身；**9 个模型交互场景**。
- 核心：**35 个旅行约束场景**，包括同名访问、跨天、预约错日／迟到／重叠、闭馆后停留、自动重排新交通不足、实际工具证据、证据旧版／过期／坐标变化、避雨缺资料／增加已知降水暴露、整个批次回滚、规范化前后端一致。此次回归约束违反率 0，预期成功编辑率 100%。这是确定性契约回归，不能解释为真实模型有 100% 成功率。
- React DOM：实际 App 的单项编辑、预览取消／应用、组合一帧撤销、重做、旧预览、迟到的停止响应、no-op、落盘／重开。离线 DOM 与 PWA worker、M27／M29 既有编辑与导出回归也检查。
- 产物位于 gitignore 的 `frontend/test-artifacts/m30/`：`backend-evaluation.json`、`core-evaluation.json`、路线与导出文件。记录逐场景成败／延迟、约束违反率、修改成功率、来源契约覆盖、已报告 token／工具调用／HTTP 与未知费用。合成来源覆盖只检查字段契约，不验证真实场馆资料。

本轮不调用付费模型；服务商 HTTP 由 fixture 模拟，地名对应真实旅行场景，坐标／开放资料／预约为合成数据。DOM 是 Node + jsdom，不是浏览器或真机验收。真实用户效果、真实模型的工具参数兼容性、全链路延迟与费用尚未测得；部署后应按同一场景与指标补录，不能将测试数值用作宣传承诺。
