# M29 · 天气评估与局部调整

日期：2026-10-01。实现、生产构建与自动化已完成；Open-Meteo 成都／北京公开接口验证通过。和风真实凭据调用、手机途中使用和生产部署仍待人工验收。

打开行程面板「☂ 按天气调整」，先确认出发日期、当天起止时间、停留和开放资料，再在「确认属性／安排」标明实际游览区域。室内、室外、混合、未知均由用户确认；地点名称不会自动决定分类。下雨影响游览的开关只影响室外活动，交通步行仍会独立检查。

打开规划页时最多自动查询一次缺失／过期天气，可按天手动刷新。服务关闭或网络失败会说明原因，编辑、导航与导出继续可用。没有浏览器关闭后的监测、推送或定时提醒。出行视图默认折叠天气面板，保持下一站卡片的操作位置；展开即可评估与预览。

## 服务配置

凭据只保存在后端环境变量／本地 `.env`，不要填入前端 BYOK，也不写入行程。未配置默认关闭；有和风 Host＋JWT 时默认使用和风。配置无效时不静默切换供应商。

```dotenv
ITERTRIP_WEATHER_PROVIDER=qweather
ITERTRIP_QWEATHER_HOST=your-account.xy.qweatherapi.com
ITERTRIP_QWEATHER_TOKEN=自行生成的JWT
```

采用当前和风坐标接口 `/weather/v1/hourly/{latitude}/{longitude}`，请求 168 小时、当地时间与中文，使用专属 Host 和 JWT。没有继续使用将废弃的 v7 城市接口；JWT 由部署者按官方流程生成、更新，当前不保存私钥或自动签发 Token。

无和风权限时可显式使用 Open-Meteo：

```dotenv
ITERTRIP_WEATHER_PROVIDER=open_meteo
# 商业部署填写客户 API Key，会自动使用 customer-api.open-meteo.com
# ITERTRIP_OPEN_METEO_KEY=
```

其公开接口可用于非商业评估，商业接口使用客户 Key；供应商要求见[定价与用途](https://open-meteo.com/en/pricing)。页面和 HTML 显示数据归属、来源链接；数据按行程时段整理，保留 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 链接。重启后端并 `start.ps1 -Rebuild` 更新前端；已有 PWA 在保存草稿后主动应用新版。

## 数据与判断

- `place/hotel.weather_exposure`：`environment`、`rain_sensitive`、`source=user`、`place_name`、`confirmed_at`。重命名后需重新确认。
- `route.weather[]`：供应商、来源／归属、读取时间、发布时间（未提供时为 null）、WGS84 地点区域、时区、粒度、forecast/historical、实际有效范围、逐小时区间与降水值、刷新失败信息。
- `route.weather_policy`：降水概率与每小时降水阈值，默认 60%／0.5 mm。任一达到阈值即提示；修改可撤销。
- 每个小时用带偏移的 ISO 开始／结束，采用左闭右开区间。Open-Meteo 的累计降水与概率表示前一小时，解析时减一小时；和风 v1 以 forecastTime 与 mm/h 强度建立小时区间。两者都保留空值，缺值不能当作无雨。
- 只有已确认境内坐标才查询。后台迭代 GCJ-02 → WGS84，再四舍五入到 0.001°，同位置去重；前端仅匹配 3 km 内区域。天气不是街道级真值，也不保证区域内每个地点的天气一致。
- 预报读取超过 30 分钟、刷新失败、已知发布时间超过 6 小时、时区不符、历史天气、超出有效范围、过去时段或小时缺口均为未评估。仅每日数据只能提供当天参考，不能推断某小时雨停。

室外游览与等待采用预计到达至离开时段。交通数据不提供准确步行子段时刻，因此有步行的交通段在起终点区域分别检查整段耗时与缓冲，属于保守评估；超过 10 km 的交通另标沿途天气未覆盖。缺少交通耗时／步行距离时不按零计算。室内外混合或未知不被视作安全室内。

天气和排程有各自的未知列表。地点即使无降水提醒，仍须通过开放、最后入场、预约、停留、日期与结束时间检查，才能作为可应用候选。

## 候选、预览与撤销

每次最多 12 个局部候选，按以下顺序检查，不宣称全局最优：

1. 当天开始提前／推迟 1、2、3 小时，保留当天结束时间；已完成当天不改开始。
2. 最多 4 对日内可移动站点交换，至少包含一处室外活动。
3. 最多 2 对相邻两天的室外／室内站点交换。

保留所有地点、酒店、访问次数、必去标志、人工开放资料与预约。固定、已完成站点的位置、开始和离开时间必须保持相同；确认不了原固定时刻时也拒绝修改。跨天重新检查适用日期与闭馆日。新室内替代点目前只提示手工查阅，不自动添加未核验地点。

先利用仍有效的交通快照评估时间调整；需要新相邻交通段时，合并去重后最多查询 12 个交通段，复用 M26 的单轮 24 次外部请求／40 秒预算。预算之外或无法获得耗时的候选拒绝应用。未找到通过检查且降水暴露减少的候选时保留原路线，列出缺失或冲突原因，不声称所有可能路线都不可行。

预览显示改动数、预计结束、风险检查数、交通时间／步行／费用变化；只有前后完整覆盖时才计算差值。起终点风险检查可能重复覆盖同一交通段，不把累计检查分钟宣称为真实淋雨时长。交通是查询时估算，不是未来交通预报；调整开始时间须用户确认。

取消预览不写入行程。确认时再次验证快照时效、路线版本和私有出行进度，一次写入共享撤销栈。异步查询到达前发生编辑、撤销或进度变更，旧结果作废。天气查询／预览期间阻止 PWA 更新；离线保存、清理缓存均保留天气记录及原读取时间。HTML 和 JSON 导出带走数据，HTML 使用相同规则显示，没有实时天气请求或供应商凭据。

模型生成的新路线不能自签天气、来源或室内确认；模型编辑只能沿用用户已有属性、预报和阈值。天气算术与候选由确定性代码执行，保持单模型策略。

## 接口预算

`POST /api/route/weather` 接收 1–12 个地点。单轮最多 12 个区域请求、总 30 秒、单请求 8 秒；全局最多 2 个在途请求、30 次／分钟。成功缓存 30 分钟、上限 256 个区域，同位置在途合并；失败不缓存成无雨。鉴权／配额错误熔断 60 秒，网络失败 30 秒。响应为 `{results,error,calls}`；整体超时时 calls 为 null，避免伪称未调用。

旧预报刷新失败时保留原时间和数值，附 `refresh_error`，不参与当前天气判断。供应商目前未返回可用发布时间的适配统一为 null，界面明确「供应商未提供」；读取时间不冒充发布时间。
