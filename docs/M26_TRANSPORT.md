# M26 · 独立交通段与真实耗时

日期：2026-09-30。状态：功能已落地；前后端契约、DOM 集成、M25 回归与生产构建通过，并已完成一组高德真实接口比较。

## 用户可以做什么

规划视图的每天时间线新增「当天交通」。选择默认步行／公交／驾车，点「比较当天交通」查询相邻站点。
交通条目插在目的地之前，支持每段覆盖默认方式、比较三种方式、设置独立的额外缓冲。
每天汇总已知交通耗时、步行距离和费用估算，标出已知段数；缺项显示未知，不算成零元或零分钟。
出行视图的下一站显示对应交通结果。查询、方式和缓冲存进 route JSON，与手改路线共用撤销／重做入口。

D1 不默认假设已经入住酒店，可勾选「从当天酒店出发」。D2 起默认从前一晚酒店出发，晚上返回当天酒店；
换酒店时起终点分别属于两晚。没有酒店时从第一个景点开始计算，首站之前的移动不做虚构估算。
相邻同名同坐标点不增加交通段。空白游玩日仍可形成前一晚酒店到新酒店的转移段。

保持原景点顺序。地图直线仍只表示地点顺序，没有绘制道路几何；本阶段也不计算按时钟推进的到达时间（M27）。
驾车耗时用于打车比较时，不包含叫车等待与上车接驳；出租车参考价与道路收费分开列出。
公交直接使用提供商的方案总耗时，不再叠加其接驳步行；实际等车与未来班次变化由用户额外留缓冲。

## 契约与兼容

前后端类型：`frontend/src/types/route.ts`、`backend/engine/schema.py`。
网页与导出共用 `shared/transport.js`，用于身份规范化、相邻段推导、签名、过期判断及汇总。

| 字段 | 语义 |
| --- | --- |
| place／hotel `id` | 每次访问的稳定本地身份；首次打开旧路线时分配并持久化，拖动或修改保留 |
| `poi_id`／`city_code` | 可选高德 POI 元数据；只从实际选中的 POI 保留，不由模型猜测 |
| day `traffic_mode` | 当天默认 `walk`／`bus`／`car` |
| day `start_from_hotel` | 是否从酒店出发；D1 当天酒店，后续天前一晚酒店 |
| day `transport[]` | 每段 `from_id`、`to_id`、可选方式覆盖与 `buffer_min`（0–180） |
| segment `snapshot` | 参数签名与三种方式的查询快照，与地点数据分开存放 |
| option | `status`、秒／米单位的耗时与距离、可空费用／道路收费、公交线路说明、查询时间、来源 |

缺字段的旧 JSON／HTML 可导入。后台日期检查与坐标校准通过 Pydantic 保留交通字段。
AI 改路线时明确要求回显身份；前端保留用户的交通设置和已有快照，拒绝模型提供的交通计算结果。
模型漏掉 ID 时仅在旧对象唯一匹配的情况下恢复；重复地点匹配有歧义时分配新 ID，避免把旧进度转给另一站。
M25 已有出行进度可迁移到稳定 ID；路线顺序修改后重复访问也各自保留进度，改名／坐标仍需要重新确认。

段签名包含提供商版本、目的地、起终点 ID、名称、GCJ-02 坐标、来源／置信度、备注与 POI 元数据。
新增／删除／拖动后重建邻接关系；参数变化丢弃不匹配快照。三种方式一次比较，切换已查过的方式可以直接选择相应快照。
每日方式、单段方式、缓冲与快照都经同一历史栈；查询落盘另要求路线对象仍是请求发起时的版本。
编辑、撤销或重做期间到达的异步旧响应不能应用，即使后来恢复到了相同的坐标组合。

## 后端接口与预算

`POST /api/route/transport`：请求 `edges[]`（`from`、`to`、`signature`）和可选 `modes[]`。
最多 12 段、三种方式；响应 `results[]` 返回签名和 options，`stats` 返回请求数、缓存命中、并发去重、预算、原因与耗时。
只由后端读取 `ITERTRIP_AMAP_KEY`／后台高德配置，Key 不进入前端、路线或导出。无需 LLM。

使用高德 v3 步行、公交、驾车路径服务。坐标以 GCJ-02 的经度、纬度和六位小数传入。
公交用起终点逆地理编码确认城市码，再传入 `city`／`cityd`；不把「湖南·长沙」等目的地原文当城市参数。
每种方式选择返回方案中耗时最短的可用结果；展示可用的方案总耗时、距离、步行距离与费用。
驾车使用可用的 POI ID，并以 `extensions=all` 获取出租车参考价；道路收费另列。

| 限制 | 实现 |
| --- | --- |
| 请求预算 | 每次最多 24 次外部调用（含公交城市查询），开始新调用前检查 40 秒预算 |
| 超时与重试 | 单次 HTTP 超时 8 秒；不自动重试，连续两次网络／响应异常停止本次查询 |
| 限流 | 进程内每分钟最多 60 次请求，至少间隔 350ms 预约请求时隙；排队超过请求预算则停止 |
| 配额与权限 | Key／配额／频率错误停止后续调用，并在该 Key 上熔断 60 秒 |
| 去重与缓存 | 相同参数共享正在执行的任务；最多 512 项、15 分钟进程内缓存，仅存规范化指标与城市码 |
| 过期可见性 | 缓存命中保留原查询时间；快照超过 15 分钟标为历史，不计入当前汇总；页面与导出每分钟刷新显示 |

仅查询相邻站点，不默认产生全量两两矩阵。一天超出 12 段时，剩余段可单独比较。
没有 Key、无路径、超时、预算／配额耗尽：保留行程，显示具体原因与「交通耗时未知」。
缺坐标、城市中心、mock、模型／搜索猜测或已有待确认标记的点不查询精确耗时；先通过编辑器确认坐标。
网络异常只返回固定说明，不回显含 Key 的 URL、供应商错误正文或异常堆栈。

## 导出

HTML／JSON 保存查询快照、来源和时间，脱离后端仍可查看。HTML 无 Leaflet 时也保留交通与导航清单。
HTML 内的手改、删除／排序导致段参数变化时，不匹配的耗时不再展示为当前结果。
导出文件只展示快照，不调用路径接口，不携带高德 Key；刷新计算回到网站操作。
